# 测试用例生成 skill

这个 skill 用来把需求材料直接整理成真实的测试用例文件。

## 你需要提供什么

- 本地单文件路径
- 本地目录路径
- 在线需求文档 URL（Confluence、PRD 链接、共享文档等）
- 粘贴的需求文本
- IMA 知识库 / 笔记（通过 `ima-skill` 自动联动检索已有文档）

## 它会做什么

- 读取并解析你提供的内容（包括通过 URL 获取在线内容、自动从 IMA 知识库拉取已有文档）
- 提炼功能模块、场景分类、测试范围、风险和待确认问题
- 生成 XMind 文件：`{业务范围名称}.xmind`（按业务命名，而非统一 testcases）

## 默认处理方式

- 单个文件：默认合并生成一套测试用例
- 同一目录：默认合并生成一套测试用例
- 单个 URL：默认合并生成一套测试用例
- IMA 知识库文档：自动按文档主题或关联模块合并生成一套测试用例
- 多个离散路径（含混合 URL+文件+知识库）：先按内容关联性判断是否应该合并；判断不稳定时先确认
- 即使合并生成，也会在内容中保留功能模块分组

## 适合什么场景

- 你已经有需求文档、页面说明或功能文本
- 需求文档存放在 IMA 知识库或个人笔记中，希望直接基于已有文档生成用例
- 你希望直接得到测试用例文件，而不是只在对话里讨论测试点
- 你希望输出同时覆盖阅读、执行和结构化展示三种用途

## 支持的输入类型

- 文档与文本：`MD`、`TXT`、`HTML`、`HTM`、`DOCX`、`DOC`、`PDF`
- 在线内容：通过 URL 获取的网页、在线文档或共享链接
- IMA 知识库与笔记：通过 `ima-skill` OpenAPI 获取的知识库文档与个人笔记正文
- 结构化测试数据：`JSON`

## 输出内容

最终测试用例默认包含这些字段：

- `功能模块`
- `场景分类`
- `用例标题`
- `测试步骤`
- `预期结果`
- `优先级`
- `测试类型`

## 测试设计规范与防漏 Checklist
 
生成测试用例时，内置并遵循资深 QA 启发式自检规范，确保超越字面需求复述，覆盖高频隐患场景：

### 维度一：交互与前端体验
1. **跨页面/跨场景状态同步**：A 页面改动状态后，验证关联页面、列表项与全局状态是否实时联动。
2. **操作撤回后重新触发**：点击取消/拒绝/关闭弹窗后，验证再次进入同一流程是否仍能正常走通。
3. **输入残留与表单清理**：关闭弹窗、切换 Tab 或下拉选项后，验证临时输入项合理清空，避免脏数据残留。
4. **极值、边界与空状态展示**：超长文本防越界截断、数值极限精度，以及数据为 0、网络断开时的友好空状态占位。
5. **国际化与多时区/多分辨率适配**：跨时区时间转换与跨天统计临界点校验，小屏或系统高缩放 DPI 下弹窗与操作列防遮挡溢出。

### 维度二：业务流与状态机
6. **状态机逆向与非法跃迁**：验证状态流转单向性，终态不可逆，拦截非法跨越流转。
7. **前置状态变体**：枚举关键初始状态（如已配置/首次使用、开启/关闭、新老数据）下的表现差异。
8. **隐式路径延伸与副作用联动**：覆盖返回上一页、页面刷新等隐式触发时机；验证消息触达、操作日志落库与统计看板更新等副作用。
9. **批量操作与部分成功容错**：批量处理时验证部分失败容错策略（回滚 vs 继续）、失败明细展示与跨页全选逻辑。

### 维度三：异常与安全防护
10. **失败/拦截防绕过**：校验报错或权限拦截后，验证用户无法跳步或通过快捷方式绕过。
11. **多用户并发冲突与数据越权**：多管理员并发编辑同一单据的乐观锁机制（防覆盖）；多租户隔离与 URL 越权拦截。
12. **离线缓存、Token 失效与会话中断**：长表单填写中 Token 过期时的无感刷新/重授权机制（防内容清空）；异地登录踢出提示。

### 维度四：系统架构与鲁棒性
13. **幂等性与防重复提交**：快速连击保存/提交、弱网重试时，验证按钮置灰防抖与服务端防重复提交/扣费。
14. **历史存量数据与版本兼容性**：新增必填字段或枚举变更后，验证存量老数据打开、查看与编辑时不会引发白屏崩溃。
15. **异步任务与长耗时状态闭环**：异步导入/导出/转码时的 Processing 态保持、排队限流、超时兜底与结果通知闭环。
16. **第三方依赖超时与熔断降级**：支付网关、OSS、短信等外部依赖超时或不可用时的业务降级与友好提示。

### XMind 导图标注规范

- **`#` 注释/忽略节点**：以 `#` 开头的节点（如 `# 暂不测试`）自动作为草稿分支，不计入正式用例评审。
- **`【待确认】` 疑问节点**：需求存在歧义或待对齐细节时，前置 `【待确认】` 或 `?` 标识，便于评审聚焦。
- **具象断言**：预期结果节点杜绝“操作正常”等模糊词，明确具体界面表现、Toast 提示、按钮状态与数据落点。

## 使用方式

可直接复制使用（替换为你的实际内容）：

文件输入：
```text
请使用 create-testcases，读取以下文件，先梳理需求点给我确认，确认后再生成测试用例：C:\需求文档.docx
```

目录输入：
```text
请使用 create-testcases，读取以下目录，先梳理需求点给我确认，确认后再生成测试用例：C:\需求目录\
```

URL 输入：
```text
请使用 create-testcases，读取以下 URL，先梳理需求点给我确认，确认后再生成测试用例：https://example.com/prd
```

文本输入：
```text
请使用 create-testcases，根据以下需求文本，先梳理需求点给我确认，确认后再生成测试用例：<粘贴需求文本>
```

IMA 知识库联动输入：
```text
请使用 create-testcases，从 IMA 知识库中查找「会员充值与结算」相关的已有需求文档，并在其基础上生成测试用例。
```

### IMA 知识库联动机制

当用户指定知识库/笔记名称，或请求为某个业务功能生成测试用例时，Agent 会自动联动 `ima-skill`：

1. **搜索定位**：调用 `search_knowledge_base` / `search_knowledge`（或笔记 `search_note`）检索相关功能文档。
2. **提取内容**：调用 `get_media_info`（或笔记 `get_doc_content`）拉取文档原文或正文。
3. **基于已有文档设计**：以提取到的已有文档为需求基线，提炼业务流程与边界规则并生成测试用例。
4. **透明追溯**：在产物中记录引用的 IMA 知识库文档来源。

### URL 输入机制

URL 输入采用 **agent 桥接**方式工作：

1. agent 使用 `webfetch` 获取 URL 内容
2. agent 将内容解析为结构化测试用例 JSON
3. 通过 `-InputUrl` + `-InputJsonText` 参数传给导出脚本
4. 导出结果的 `inputJson` 字段会记录原始 URL 来源

**脚本参数说明：**

| 参数模式 | 行为 |
|---|---|---|
| `-InputUrl <url>`（单独） | 输出 agent 桥接指引信息，指导 agent 下一步操作 |
| `-InputUrl <url> -InputJsonText '<json>'` | 正常导出，且 `inputJson` 字段记录为 `url:<url>` |
| `-Preview`（开关参数） | 预览模式，只输出分析摘要 JSON 到 stdout，不生成任何文件 |

## 临时文件约束

- 执行过程中不得在 skill 根目录生成调试中间产物。
- 不得把用户输入文档复制成 `temp_doc.docx`。
- 不得生成 `extracted_content.txt`、`补充逻辑-提取内容.txt` 等调试提取文件。
- `DOCX` 读取应走导出脚本内置的内存解析逻辑；`DOC` / `PDF` 读取应走 Office COM 只读读取。
- 除用户明确确认外，只允许生成最终导出的 `.xmind` 文件，且输出位置应为 `exports/` 或用户指定目录。

## 环境与维护

### 迁移清单

1. 将迁移包解压到目标工作区的 `<workspace>\.opencode\skills\create-testcases\`
2. 至少确认这些内容一起带走：`SKILL.md`、`README.md`、`package.json`、`package-lock.json`、`scripts/`、`templates/default-template.xmind`、`fixtures/`
3. 新电脑需要：`Node.js >= 20`、Windows PowerShell
4. 如需 Mockplus 抓取能力，必须安装 Playwright Chromium；如需解析 `DOC` / `PDF`，还需要本机可用的 Microsoft Word COM 环境
5. 进入 skill 根目录后执行完整初始化：

```powershell
cd <workspace>\.opencode\skills\create-testcases
npm install
npm run setup:browsers
node .\scripts\verify-runtime.mjs
npm test
```

6. 也可以执行初始化脚本安装依赖并检查运行环境：

```powershell
powershell -ExecutionPolicy Bypass -File ".\scripts\setup-runtime.ps1"
```

7. 如果使用第 6 步，仍需单独安装 Mockplus 抓取所需 Chromium，并运行完整测试：

```powershell
npm run setup:browsers
node .\scripts\verify-runtime.mjs
npm test
```

8. 迁移包不携带 `node_modules/`、`.git/`、`exports/`；`node_modules/` 通过 `npm install` 重新生成，`exports/` 会在导出时按需创建
9. 最后做一次最小验证：
   - 一次本地文件输入
   - 一次 URL 输入（可选：验证 `webfetch` 流程）
   - 一次 Mockplus 公开分享链接输入（验证 Playwright Chromium 抓取流程）

### OpenCode 自动识别

- 如果只是本地运行脚本，目录放哪里都可以
- 如果希望 OpenCode 自动识别成 skill，建议把目录放到新电脑工作区的：

```text
<workspace>\.opencode\skills\create-testcases\
```

- 也就是让 `SKILL.md` 的最终位置类似：

```text
C:\YourWorkspace\.opencode\skills\create-testcases\SKILL.md
```

- 放到这个位置后，重启或重新进入该工作区，再让 OpenCode 重新发现本地 skills

### 目录说明

- `fixtures/` — 测试夹具目录，包含导出测试的 fixture 数据
- `exports/` — 示例产物目录，包含历史导出的测试用例示例，不参与正常运行流程

### 常见问题

- 只复制脚本文件会缺少模板和运行配置
- 没执行 `npm install` 会导致依赖缺失
- “本地能运行” 和 “OpenCode 能自动识别为 skill” 是两回事；自动识别时要特别检查 `SKILL.md` 是否位于 `<workspace>\.opencode\skills\create-testcases\`
