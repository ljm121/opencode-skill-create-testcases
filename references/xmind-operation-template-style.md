# XMind 测试点模板生成规则

`templates/测试用例生成规范.xmind` 是生成规则模板，不是最终视觉模板。使用它时重点理解两类占位符：

- `[]`：替换为需求里的真实对象名称，例如字段、筛选项、按钮、操作入口。
- `{}`：替换为围绕该对象生成的测试点，例如取值规则、显示规则、填写规则、点击前校验、点击后数据校验。

生成结果不要保留 `[]` 或 `{}`。不要要求一级、二级、三级节点固定叫什么；节点层级由业务操作和测试点之间的从属关系决定。

## 生成口径

- 先识别业务操作，再围绕操作生成测试点。常见操作包括列表、新增、编辑、删除、详情；模板未覆盖的操作按语义补充相近测试点。
- 节点必须来自需求或示例推导出的真实业务对象。没有前置条件时不要生成“前置条件”节点；没有操作按钮时不要生成“操作按钮”节点；不要为了套模板硬写泛化节点。
- 列表类操作优先覆盖数据范围/来源、列表内容字段、字段组合展示、空值展示、格式、hover/链接/图标、条件提示、操作列显示条件、筛选控件、筛选规则、排序、分页。参考 `templates/列表-示例.xmind` 的颗粒度。
- 新增类操作优先覆盖选择/进入步骤、带出信息、字段必填/选填、提示文字、默认值、控件类型、选项范围、输入限制、上传/下载/预览/删除、动态子模块、联动清空、二次确认、按钮点击时校验、提交后的数据与状态校验。参考 `templates/新增-示例*.xmind`。
- 编辑类操作优先覆盖可编辑状态、入口方式、已有信息带出、字段是否可修改、与新增不同的限制、状态差异、按钮差异、重新计算/保留旧值、编辑后数据与状态校验。参考 `templates/编辑-示例*.xmind`。
- 详情类操作优先覆盖入口、字段取值、字段显示/隐藏、空值展示、条件分组/tab、链接跳转、hover提示、附件可见性、页面动作；只有存在页面动作时才写按钮。参考 `templates/查看详情-示例.xmind`。
- 删除类操作优先覆盖入口、是否二次确认、弹窗标题/提示、取消结果、确认删除后的后台/前台/数据状态校验。

## 节点关系

- 同一对象的多个测试点通常作为兄弟节点，例如 `手机号 -> 填写规则` 与 `手机号 -> 格式校验`。
- 一个测试点需要继续拆验时生成子节点，例如 `点击按钮后的校验 -> 数据校验 -> 新增一条记录`。
- 最后一级测试点如果需求明确给出“不符合预期时的提示或表现”，继续挂子节点说明具体表现，例如字段下方红字、toast 文案、按钮置灰、弹窗不关闭、页面不可访问、数据不变化、原数据保留等；需求没有明确说明时不要补写泛化提示。
- 业务对象下面不够具体的 `{规则}` 要改写成可执行测试点，例如 `显示已脱敏手机号`，不要只写 `规则`。
- 可以基于需求增加模板没有列出的测试点，但要挂在最接近的业务操作或对象下。

## xmindOperations 建议结构

```json
{
  "operation": "新增",
  "preconditions": ["有新增权限"],
  "entry": ["列表页点击新增"],
  "fields": [
    { "name": "手机号", "testPoints": ["填写规则", { "title": "格式校验", "children": ["错误时提示手机号格式不正确"] }] }
  ],
  "buttons": [
    { "name": "保存", "testPoints": [{ "title": "点击按钮后的校验", "children": ["数据校验", "状态校验"] }] }
  ]
}
```
